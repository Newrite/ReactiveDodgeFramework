# ECB SCAR annotation string crash (SE 1.5.97)

Input: `F:/SkyrimDumps/SkyrimDiag_Crash_20261028_022520_959.dmp`
and CrashLogger 2026-10-28 02:25:28. NPC Bear Clan, FF000BD6, drawing a warhammer.

The probable stack is SCARData::Read -> AttackReach -> GatherState -> ProcessActor.
Read line 188 constructs a string_view from an annotation's hkStringPtr::c_str().
The failing address is 0x231093C0 in the CRT string length routine.

Code bytes read directly from the dump show:

```
EnhancedCombatBehavior+721B0 lea rcx, [rsi+8]  ; annotation.text
EnhancedCombatBehavior+721B4 call EnhancedCombatBehavior+8C000
EnhancedCombatBehavior+721C7 mov rcx, rbx
EnhancedCombatBehavior+721CA call ...         ; string length
EnhancedCombatBehavior+721CF ...              ; return address in crash stack

EnhancedCombatBehavior+8C000 mov eax, dword ptr [rcx]
EnhancedCombatBehavior+8C002 mov ecx, 0FFFFFFFEh
EnhancedCombatBehavior+8C007 and rax, rcx
EnhancedCombatBehavior+8C00A ret
```

CommonLib's hkStringPtr::data() uses `_data & ~kManaged`, where the flag enum is
unsigned 32-bit. The resulting 32-bit mask discards the upper 32 bits of a valid
x64 pointer. This is a deterministic pointer-width defect, reached while ECB
inspects SCAR action annotations, independently of submitting a dodge to RDF.
The original annotation heap page is absent from this minidump; its full original
pointer and annotation text cannot be recovered from that page.

Fix: local ECB ReadHavokString helper copies the stored pointer representation
with memcpy and applies `~std::uintptr_t{1}`. No call to the defective CommonLib
accessor. Other strings in SCARData are std::string or BSFixedString and are not
changed. The shared CommonLib checkout is not modified.

Regression: `xmake build -P . havok_string_test` and
`xmake run -P . havok_string_test` in the ECB fork. Checks null, both flag states,
multiple addresses above 4 GiB, and reading an actual tagged string. Passed.
ECB rebuilt successfully for SE 1.5.97 and deployed to the existing VanillaLike
test override mod. New DLL disassembly at RVA 0x721C1 confirms a qword pointer load
followed by `and rax, 0xfffffffffffffffe`; the defective accessor is bypassed.
DLL SHA256: `67e94af558a9f8bded4b77a079b2f667dfc027a07d14c407e7cf92f17f96caa9`.
Previous installed ECB DLL/PDB are backed up under
`_work/ecb-rdf-se/before-scar-string-hotfix-20261028`.
The test package/source ZIPs and manifests are updated. Gameplay verification
remains with the user; no launch performed.
