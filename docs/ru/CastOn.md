# CastOn: заклинания на додж

CastOn кастует заклинания, когда актор доджит или делает идеальный додж. Каждое правило задаёт:
- когда оно срабатывает (триггер);
- при каких условиях (дерево условий, как в OAR);
- что, кто и на кого кастует;
- сколько это стоит;
- в какой момент доджа срабатывает.

Правила работают для любого актора, не только для игрока. Весь CastOn включается и выключается одной настройкой
`[CastOn] bCastOn` → меню F7 → «Стоимость и правила» → «Правила CastOn».

## 1. Где правила и как их редактировать

- **Файлы:** `SKSE/Plugins/ReactiveDodgeFramework/CastOn/*.json`.
  - Рядом с файлом может лежать `<имя>.user.json`. Он заменяет файл **целиком**, как `user.json` у OAR.
  - В комментариях допустимы `//`.
  - Неизвестный ключ — ошибка: правило с опечаткой не загрузится, и причина появится в логе и в редакторе.
- **Редактор в игре:** F7 → «Стоимость и правила» → кнопка **«Редактор правил CastOn»**.
  - **Слева** файлы, их правила (галочка — «Включено») и пресеты; кнопки «+ Правило», «+ Пресет».
  - **Справа** выбранное правило.
  - **«Сохранить»** записывает `<имя>.user.json` (файл мода не меняется) и сразу перезагружает правила в игре.
  - **«Перечитать файлы»** отбрасывает несохранённые правки.
  - **«Удалить файл пользователя»** возвращает файл мода.
  - **«Новый файл»** создаёт свой файл правил.
- **Живая проверка.** Пока окно открыто, у каждого условия видна отметка для игрока: ✓ выполнено, ✗ нет, ? не
  определить (нет такого участника, не найдена форма или пресет). Атакующим при этом считается цель игрока в бою.
- **«Выполнить сейчас»** кастует заклинания правила прямо сейчас за игрока, чтобы посмотреть каст. Условия при этом
  только пишутся в лог.
- **Схема для VS Code:** `rdf_caston.schema.json` лежит рядом. Строка `"$schema": "./rdf_caston.schema.json"` в файле
  включает проверку и подсказки имён.
- **Пример:** `RDF_Examples.json`, все его правила выключены.

Формы указываются как `Plugin.esp|0xID` (ID как в xEdit, без байта порядка загрузки) или EditorID. EditorID есть
всегда у кейвордов; у заклинаний и эффектов — только с плагином, сохраняющим EditorID (например, po3 Tweaks).

## 2. Правило

| Поле JSON | В редакторе | Что значит |
|---|---|---|
| `name` | «Имя» | имя для лога и редактора |
| `enabled` | «Включено» | выключенное правило не загружается |
| `trigger` | «Триггер» | `Dodge` — додж начался (свежий или в цепочке); `PerfectDodge` — i-frames поймали удар в окне идеального доджа |
| `priority` | «Приоритет» | правило с большим приоритетом проверяется раньше |
| `exclusive` | «Эксклюзивное» | если сработало, правила ниже по приоритету для этого триггера не проверяются |
| `conditions` | «Условия» | должны выполняться все (раздел 3) |
| `casts` | «Касты» | одно или несколько заклинаний (раздел 4) |
| `cost` | «Стоимость» | раздел 5 |
| `timing` | «Тайминг» | раздел 6 |
| `limits` | «Ограничения» | `cooldown` («Кулдаун», секунды на актора), `oncePerChain` («Раз за цепочку»), `chance` («Шанс (проценты)», 0–100) |
| `extends` | «Из шаблона» | правило построено на шаблоне файла (раздел 7) |

**Участники:**
- `Dodger` — тот, кто доджит;
- `Attacker` — тот, чей удар поймали. Он известен **только** на `PerfectDodge`; на `Dodge` условие на атакующего не
  выполняется;
- `CombatTarget` — цель доджера в бою.

Условие на отсутствующего участника не выполняется, с отрицанием или без.

## 3. Условия

Условие — узел дерева. В редакторе его строка показывает живую отметку, тип и краткую сводку. Как в OAR:
- раскрыть узел — увидеть параметры;
- перетащить строку — поменять порядок;
- правый клик — копировать, вставить ниже, дублировать, удалить;
- галочка слева временно выключает условие (`disabled`).

Общие поля условия:

| Поле JSON | В редакторе | Что значит |
|---|---|---|
| `kind` | «Условие» | тип (таблица ниже) |
| `negated` | «НЕ» | наоборот |
| `subject` | «Чьё» | `Dodger`, `Attacker`, `CombatTarget` |
| `form` | «Кейворд» / «Перк» / «Раса» / «Фракция» / «Маг-эффект» | форма для типов, которым она нужна |
| `text` | «Тип экипировки» / «Actor value» / «Слой» / «Направление доджа» / «Пресет» / «Функция» | текстовый параметр |
| `hand` | «Рука» | `Right`, `Left`, `Either` |
| `mode` | «Значение» | для actor value: `Current`, `Max`, `Percent` (от максимума, 0–100), `Base` |
| `compare` / `value` | «Сравнение» / «Число» | `None` (без сравнения), `Eq` =, `Ne` ≠, `Lt` <, `Le` ≤, `Gt` >, `Ge` ≥ |
| `disabled` | галочка в строке | выключено: условия как будто нет; группа, в которой всё выключено, считается выполненной |
| `comment` | «Комментарий» | заметка, видна в строке условия |

Типы (`kind`):

| Тип | Что проверяет |
|---|---|
| `And` / `Or` | группа: выполняются все / хотя бы одно условие внутри (`children`) |
| `HasKeyword` | у участника есть кейворд: на нём самом (с расой), надетом предмете или активном маг-эффекте |
| `HasEffectKeyword` | у активного маг-эффекта участника есть кейворд; со сравнением — сумма их магнитуд |
| `HasMagicEffect` | на участнике действует этот маг-эффект; со сравнением — сумма магнитуд |
| `HasPerk` / `IsRace` | перк / раса |
| `InFaction` | во фракции; со сравнением — ранг |
| `Equipped` | что в руке: Fists, Sword, Dagger, Axe, Mace, Greatsword, Battleaxe, Warhammer, Bow, Crossbow, Staff, Spell, Shield, Torch, Any |
| `ActorValue` | значение AV по имени (как в консоли: Health, Stamina, OneHanded…) со сравнением |
| `InCombat`, `Sneaking`, `Sprinting`, `Blocking`, `Attacking`, `PowerAttacking`, `IsPlayer` | состояние участника |
| `Casting` | кастует ли этой рукой |
| `FirstPerson` | додж от первого лица |
| `Layer` | где играет додж: Root, OneHand, Bow, Magic |
| `Direction` | клип доджа: Forward, ForwardRight, Right, BackwardRight, Backward, BackwardLeft, Left, ForwardLeft, Neutral |
| `ChainIndex` | номер доджа в цепочке со сравнением: 0 — первый |
| `FromStagger` | додж прервал стаггер |
| `Random` | шанс в процентах, бросок каждый раз |
| `Preset` | все условия именованного пресета (раздел 7) |
| `Vanilla` | любая функция условий игры из CK, раздел 3.1 |

**Магнитуды эффектов** у `HasEffectKeyword` и `HasMagicEffect`:
- «И неактивные эффекты» (`inactiveEffects`) — считать и эффекты, выключенные условиями заклинания, и развеянные,
  как это делает игровой HasMagicEffect. Без галочки считаются только активные;
- «Магнитуда» (`reading`), показывается при сравнении:
  - `Authored` — число как в заклинании (с перками), знак как у автора;
  - `Applied` — как эффект действует на значение: Detrimental со знаком минус.

### 3.1. Функции игры (`Vanilla`)

«Функция» (`text`) выбирается из списка функций условий игры, того же, что в CK: GetActorValue, GetIsID,
GetLevel, IsInLocation… Параметры — `args`, по полю на параметр:
- форма — пикер нужного типа;
- референс — `Dodger`, `Attacker`, `CombatTarget` или конкретный размещённый референс. Пустой первый референс
  означает другого участника, как цель у условия CK: для доджера это атакующий (или цель в бою), для остальных —
  доджер;
- actor value — по имени;
- оси X/Y/Z, пол Male/Female, источник каста Left/Right/Voice/Instant — из списка;
- остальное — число.

Результат сравнивается с «Числом». Без сравнения условие выполняется, если результат не 0. Функции, которым
нужен алиас квеста, данные пакета или скриптовая переменная, в списке не показываются. Игровые HasMagicEffect и
HasMagicEffectKeyword CastOn считает сам и с тем же правилом «И неактивные эффекты».

## 4. Касты

| Поле JSON | В редакторе | Что значит |
|---|---|---|
| `spell` | «Заклинание» | заклинание, свиток, зачарование или зелье; абилки (постоянные эффекты) не допускаются |
| `caster` | «Кастер» | `Dodger`, `Attacker`, `CombatTarget` |
| `target` | «Цель» | `Self` (сам кастер), `Dodger`, `Attacker`, `CombatTarget`, `Aim` (без цели: снаряд летит туда, куда смотрит кастер) |
| `effectiveness` | «Эффективность» | множитель силы |
| `magnitude` | «Магнитуда» | своя магнитуда; 0 — магнитуда заклинания |
| `duration` | «Длительность» | только для заклинаний концентрации: сколько секунд идёт поток (до 60) |
| `noHitEffectArt` | «Без арта» | без визуала попадания на цели |

Обратный каст (как в Reflyem): кастер `Attacker`, цель `Dodger`. Каст без своего кастера или цели пропускается с
записью в лог.

## 5. Стоимость

`mode` («Режим»):
- `Free` — бесплатно, как `Spell.Cast` в Papyrus.
- `Engine` — как настоящий каст: цена из движка (навык, перки, моды на стоимость), проверка «можно ли кастовать»,
  списание из нужного ресурса. В режиме бога — бесплатно.
  - `dualCast` («Двойной каст») — цена двойного каста.
  - `realCast` («Как настоящий») — ещё снимает невидимость и шлёт событие каста, как каст из рук.
  - Концентрация списывается каждую секунду, пока идёт поток, и останавливается на нуле.
- `Custom` — своя формула: `(flat + spellShare × цена заклинания + maxShare × максимум ресурса) × mult` из ресурса
  `value`.
  - `value` («Платит из») — `Magicka`, `Stamina` или `Health`.
  - `flat` — «Фиксированно», `spellShare` — «Доля цены заклинания», `maxShare` — «Доля максимума», `mult` —
    «Множитель».
  - Для концентрации цена за секунду умножается на длительность и платится сразу.

Для `Engine` и `Custom` есть ещё два поля:
- `shortfall` («Не хватает»):
  - `Skip` — без каста;
  - `CastAnyway` — заплатить сколько есть и кастовать в полную силу;
  - `Scale` — слабее на недоплаченную долю;
- `feedback` («Мигание HUD») — мигает полоса игрока, когда не хватает.

## 6. Момент срабатывания

| Поле JSON | В редакторе | Что значит |
|---|---|---|
| `timing.delay` | «Задержка» | секунды после триггера (от старта доджа или от пойманного удара). Если это позже конца доджа, правило срабатывает в конце |
| `timing.annotation` | «По аннотации» | если клип расставляет моменты (`RDF_CastOnClip` на 0), правило ждёт его аннотацию вместо задержки. Если её нет, срабатывает в конце доджа |
| `timing.tag` | «Тег аннотации» | правило ждёт `RDF_CastOnDodge.<тег>` / `RDF_CastOnPerfectDodge.<тег>`. Правило без тега ждёт аннотацию без тега |

Аннотации, которые ставит аниматор, описаны в [Annotations.md](Annotations.md), раздел 4. Правило PerfectDodge,
чья аннотация прошла раньше удара, срабатывает в момент удара. Цепочка завершает ожидания предыдущего доджа (они
срабатывают), а отменённый старт доджа сбрасывает его касты триггера Dodge.

## 7. Пресеты и шаблоны

- **Пресет** (`"presets"` файла, «+ Пресет») — именованный список условий. Условие `{ "kind": "Preset", "text":
  "<имя>" }` подставляет их все (И). Пресеты любого файла видны всем правилам. Если два файла называют пресет
  одинаково, побеждает первый файл по имени.
- **Шаблон** (`"templates"` файла) — частичное правило. Правило с `"extends": "<имя>"` начинается с шаблона:
  - ключи правила заменяют ключи шаблона;
  - `cost`, `timing` и `limits` сливаются по ключам;
  - условия шаблона и правила складываются (должны выполняться все).

  Редактор сохраняет такое правило целиком, без ссылки на шаблон.

## 8. Пример

```json
{
   "$schema": "./rdf_caston.schema.json",
   "version": 1,
   "presets": {
      "AttackerAlive": [ { "kind": "ActorValue", "subject": "Attacker", "text": "Health", "mode": "Percent", "compare": "Gt", "value": 0 } ]
   },
   "rules": [
      {
         "name": "Пламя в ответ на идеальный додж",
         "trigger": "PerfectDodge",
         "priority": 10,
         "conditions": [
            { "kind": "Preset", "text": "AttackerAlive" },
            { "kind": "Equipped", "text": "Spell", "hand": "Either" }
         ],
         "casts": [ { "spell": "Skyrim.esm|0x12FCD", "caster": "Dodger", "target": "Attacker", "duration": 1.5 } ],
         "cost": { "mode": "Engine", "realCast": true },
         "limits": { "cooldown": 1.5 }
      }
   ]
}
```

Поля, которых нет в правиле, берут значения по умолчанию: включено, без задержки, по аннотации, без ограничений,
бесплатно.
